1. What is a Non-deterministic Finite Automaton (NFA)?

An NFA is a 5-tuple M = (Q, Σ, δ, q₀, F) where:

Q — finite set of states
Σ — finite input alphabet
δ — transition function: Q × Σ → 𝒫(Q)   (maps to a set of states)
q₀ — initial state, q₀ ∈ Q
F — set of final/accepting states, F ⊆ Q

The key difference from a DFA is the transition function: δ maps a state and a symbol to a set of possible next states (including the empty set ∅). This "non-determinism" means the machine can be in multiple states simultaneously.

An NFA accepts a string w if any possible computation path reaches an accepting state.

2. What is a Deterministic Finite Automaton (DFA)?

A DFA is also a 5-tuple M = (Q, Σ, δ, q₀, F), but with a stricter transition function:

δ : Q × Σ → Q   (maps to exactly one next state)

In a DFA:

  • Every state has exactly one transition per input symbol.
  • There is no ambiguity — the next state is always uniquely determined.
  • Simulation is linear in the length of the input string.

A DFA accepts a string w = a₁a₂…aₙ if starting from q₀ and following transitions δ(q, aᵢ) one character at a time, the machine ends in a state q ∈ F.

Despite the apparent difference in power, NFAs and DFAs recognise the same class of languages — the regular languages. Every NFA can be converted to an equivalent DFA using the Subset Construction algorithm.

4. Subset Construction Algorithm

The Subset Construction (also called Powerset Construction) converts any NFA into an equivalent DFA. Each DFA state represents a set of NFA states that the NFA could simultaneously be in.

Intuition

When an NFA reads symbol 'a' from state q, it may transition to several states at once. We represent this "set of possibilities" as a single DFA state. The DFA then tracks which sets are reachable.

Pseudocode

FUNCTION subsetConstruction(NFA M = (Q, Σ, δ, q₀, F)):

  initial_set ← {q₀}
  DFA_states ← ∅
  DFA_trans ← ∅
  queue ← [initial_set]
  visited ← ∅

  WHILE queue ≠ ∅:
    S ← dequeue(queue)
    IF S ∈ visited: CONTINUE
    visited ← visited ∪ {S}
    DFA_states ← DFA_states ∪ {S}

    FOR EACH symbol a ∈ Σ:
      T ← ∪ { δ(q, a) | q ∈ S }
      DFA_trans[S][a] ← T
      IF T ∉ visited AND T ≠ ∅:
        enqueue(queue, T)

  DFA_finals ← { S ∈ DFA_states | S ∩ F ≠ ∅ }
  RETURN DFA(DFA_states, Σ, DFA_trans, initial_set, DFA_finals)

Key points

  • State labels — Each DFA state is labelled with the set of NFA states it represents, e.g. {q0, q1}.
  • Canonical order — State sets are always sorted alphabetically so {q0,q1} and {q1,q0} are treated as the same state.
  • Dead state — If δ*(S, a) = ∅, the DFA transitions to a trap state ∅ from which no accepting state is reachable.
  • Accepting states — A DFA state S is accepting iff S ∩ F ≠ ∅ (i.e. it contains at least one NFA accepting state).
  • Termination — The algorithm always terminates because there are finitely many subsets of Q (at most 2|Q|).

5. Accepting States and Dead States

Accepting (Final) States

A DFA state S (which represents a set of NFA states) is an accepting state if and only if:

S ∩ F ≠ ∅

That is, at least one of the NFA states in S is a final state in the original NFA.

Dead / Trap States

When an NFA has no transitions defined for a particular (state, symbol) pair, the result is the empty set ∅. In the DFA, ∅ becomes a dead state (also called a trap state):

  • Once the DFA enters ∅, it cannot leave (all transitions from ∅ loop back to ∅).
  • ∅ is never an accepting state.
  • It is only added to the DFA if at least one transition would otherwise be undefined.

6. Time and Space Complexity

Worst-case DFA states
O(2ⁿ)
Algorithm time
O(2ⁿ · |Σ|)
String simulation (DFA)
O(|w|)

The worst-case exponential blowup in states is unavoidable in general — there exist NFAs with n states for which the minimal equivalent DFA requires 2ⁿ states. In practice, most NFAs produce far fewer DFA states.

Once the DFA is constructed, simulating it on any input string runs in O(|w|) — linear time, reading each character exactly once.

8. Common Mistakes

⚠ Non-canonical state labels
Always sort the states in a subset label. {q1,q0} and {q0,q1} are the same DFA state — using different orderings causes duplicate states and incorrect tables.
⚠ Forgetting the dead state
If any NFA transition is undefined (δ(q, a) = ∅), the DFA needs a dead/trap state ∅. Omitting it makes the DFA incomplete.
⚠ Wrong accepting state rule
A DFA state S is accepting iff S ∩ F ≠ ∅ — if it contains any NFA accepting state, not all of them.
⚠ Confusing ε-NFA with NFA
The basic Subset Construction does not handle epsilon transitions. If your NFA has ε-transitions you must first compute ε-closures. Automata Lab's NFA→DFA module does not accept ε.
⚠ Stopping too early
Every reachable subset must be processed. Keep processing until the queue is fully exhausted.
